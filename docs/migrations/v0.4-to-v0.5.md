# v0.4 to v0.5 migration

v0.5 is currently `0.5.0-alpha.0`, not a production release.

Planning Cases, Case Events, and local Case Transactions move from v1 to v2.
Use `scripts/migrate-planning-case.mjs --artifact <name> --input <file>
--dry-run true`; free legacy objects that cannot be bound exactly return
`LEGACY_CONTEXT_INCOMPLETE` rather than being guessed. Runtime packages prefer
the generated `build-metadata.json`, so installable archives no longer require
a `.git` directory.

Admission Review v1 is stricter during this Alpha convergence: `source` and all
eight `axes` are now mandatory, and READY requires every axis to PASS. Existing
reviews cannot be guessed or promoted; rerun the fresh Reviewer against the
exact bound input.

1. Run `npm ci`, `npm run verify:ci`, and
   `pi-ticket-planctl doctor --static --json` in the new checkout.
2. Review `pi-ticket-planctl update --dry-run --json`. Managed Profile drift must
   be resolved by the operator; it is not overwritten silently.
3. Review `pi-ticket-planctl migrate --dry-run --json`, then use `--apply` only
   for the displayed local Profile paths. Existing target repositories are not
   migration destinations.
4. New Planning Cases use Checkpoint v2 and Fact Attestation v1. Convert a legacy
   Checkpoint or Delivery Graph v1 with `scripts/migrate-artifacts.mjs`; Delivery
   Graph migration requires exact Spec/body/starting-state context.
5. Admission Plan remains v1 with the same fingerprint algorithm. The v0.5
   writer additionally requires exact Reviewer and Capability bindings. An old
   unbound Plan is not eligible for formal v0.5 CLI apply.
6. Re-run active capability probes. No tuple is supported until the exact
   Pi/Subagent/Provider/model/Profile/Harness tuple has active and qualification
   evidence.

Rollback restores only retained local installation snapshots. It cannot undo an
external mutation already read back by Admission.
